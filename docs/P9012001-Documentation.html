    1. Resumo Executivo

    Programa: P9012001

    Cliente: CHESF - Cia Hidro Elétrica do São Francisco

    Sistema: S9013 - SIAF (Sistema de Informação de Aquisição e Fornecimento)

    Objetivo: Alterar/Excluir registros via ISN em modo Batch do arquivo D9013142-13

    Data de Criação: 21/03/2012

    Última Manutenção: 08/05/2012 (Documento SMP-0405/2012)

    Propósito de Negócio

    Este programa permite alterar ou excluir registros do arquivo de simulações de cobrança (D9013142-13) usando o ISN (Internal Sequence Number) como identificador. Suporta modo simulação (dry-run) e modo efetivo, permitindo ao usuário validar as operações antes de confirmar.

    Audiência

    Analistas de sistemas, auditores, equipes de modernização e gestores de operações de processamento em batch.

    Resultado da Análise

    Programa identificado como baixa complexidade técnica, mas complexidade média de modernização devido às dependências não disponíveis. Candidato a refatoração com separação de lógica de validação de acesso a dados.

    ⚠️ Aviso Operacional (do código-fonte): Antes de iniciar um novo procedimento de manutenção, verificar com o coordenador se este objeto já está no ambiente de produção.

    Pontos Críticos do Fluxo

    • Validação acumulativa: Todos os erros são acumulados em WFL-TEM-ERRO antes de encerrar, não apenas o primeiro erro.
    • Padrão NULL para campos opcionais: Campos são validados e processados apenas se forem diferentes da string literal 'NULL'.
    • Modo simulação (EFETIVA): EFETIVA = 'NAO' executa um BACKOUT TRANSACTION, permitindo visualizar mudanças sem confirmá-las.
    • CALLNAT para validação externa: L001-INDC-SITC-SIMU requer validação externa via N9013Q06, programa agora disponível em Codigo-natural/Subprogramas/N9013Q06.NSN.
    • Transação implícita: GET inicia transação; END TRANSACTION ou BACKOUT TRANSACTION a encerram.

    Gargalos Identificados

    • Impressão Dupla (ANTES/DEPOIS): Cada execução imprime o relatório R9012001 duas vezes. Em processamento em batch de alto volume, este é o custo dominante.
    • Dependência de N9013Q06: Chamada síncrona a programa externo; sem tratamento de timeout ou retry.
    • Edição de Valores Numéricos: Validação de L001-VALR-DOCM-SIMU e L001-VALR-DOCM-COBR usa EXAMINE e manipulação de string; ineficiente para altos volumes.
    • DECIDE FOR EVERY CONDITION: Processa todos os 13 campos mesmo que muitos sejam NULL; sem short-circuit.

    Recomendações de Otimização

    • Impressão condicional: Adicionar flag para imprimir ou não (ANTES apenas em relatório, DEPOIS em log apenas)
    • Cache de validações: Se N9013Q06 é chamado múltiplas vezes na mesma execução, cachear resultados
    • Validação numérica acelerada: Usar função nativa de validação numérica do Natural se disponível, em vez de EXAMINE
    • Early exit em DECIDE: Considerar múltiplos DECIDE IF aninhados com early exit, em vez de DECIDE FOR EVERY

    Escalabilidade

    • Modo batch: Processamento sequencial de registros; sem paralelismo
    • Transações: Cada registro constitui uma transação; sem batching de transações
    • Memória: Consumo mínimo; apenas 7 variáveis locais + estruturas Adabas
