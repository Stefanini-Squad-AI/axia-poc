    1. Resumo Executivo

    Programa: P9012001

    Cliente: CHESF - Cia Hidro Elétrica do São Francisco

    Sistema: S9013 - SIAF (Sistema de Informação de Aquisição e Fornecimento)

    Objetivo: Alterar/Excluir registros via ISN em modo Batch do arquivo D9013142-13

    Data de Criação: 21/03/2012

    Última Manutenção: 08/05/2012 (Documento SMP-0405/2012)

    Propósito de Negócio

    Este programa permite alterar ou excluir registros do arquivo de simulações de cobrança (D9013142-13) usando o ISN (Internal Sequence Number) como identificador. Suporta modo simulação (dry-run) e modo efetivo, permitindo ao usuário validar as operações antes de confirmar.

    Audiência

    Analistas de sistemas, auditores, equipes de modernização e gestores de operações de processamento em batch.

    Resultado da Análise

    Programa identificado como baixa complexidade técnica, mas complexidade média de modernização devido às dependências não disponíveis. Candidato a refatoração com separação de lógica de validação de acesso a dados.

    ⚠️ Aviso Operacional (do código-fonte): Antes de iniciar um novo procedimento de manutenção, verificar com o coordenador se este objeto já está no ambiente de produção.

    Pontos Críticos do Fluxo

    • Validação acumulativa: Todos os erros são acumulados em WFL-TEM-ERRO antes de encerrar, não apenas o primeiro erro.
    • Padrão NULL para campos opcionais: Campos são validados e processados apenas se forem diferentes da string literal 'NULL'.
    • Modo simulação (EFETIVA): EFETIVA = 'NAO' executa um BACKOUT TRANSACTION, permitindo visualizar mudanças sem confirmá-las.
    • CALLNAT para validação externa: L001-INDC-SITC-SIMU requer validação externa via N9013Q06, programa não disponível.
    • Transação implícita: GET inicia transação; END TRANSACTION ou BACKOUT TRANSACTION a encerram.

    10. Performance e Otimização

    Análise de Operações Críticas

    OperaçãoTipoCusto EstimadoNotas
    GET D142-13-CADS-SIMU by ISNLeitura Adabas🟡 MédioAcesso direto via ISN (índice nativo); sem varredura

    UPDATE (G1.)Escrita Adabas🟡 MédioAtualização in-place no Adabas; dependente do tamanho do registro

    WRITE(1) FORM R9012001I/O Relatório🔴 AltoImpressão formatada; executada 2x (ANTES e DEPOIS)

    Gargalos Identificados

    • Impressão Dupla (ANTES/DEPOIS): Cada execução imprime o relatório R9012001 duas vezes. Em processamento em batch de alto volume, este é o custo dominante.
    • Dependência de N9013Q06: Chamada síncrona a programa externo; sem tratamento de timeout ou retry.
    • Edição de Valores Numéricos: Validação de L001-VALR-DOCM-SIMU e L001-VALR-DOCM-COBR usa EXAMINE e manipulação de string; ineficiente para altos volumes.
    • DECIDE FOR EVERY CONDITION: Processa todos os 13 campos mesmo que muitos sejam NULL; sem short-circuit.

    Recomendações de Otimização

    • Impressão condicional: Adicionar flag para imprimir ou não (ANTES apenas em relatório, DEPOIS em log apenas)
    • Cache de validações: Se N9013Q06 é chamado múltiplas vezes na mesma execução, cachear resultados
    • Validação numérica acelerada: Usar função nativa de validação numérica do Natural se disponível, em vez de EXAMINE
    • Early exit em DECIDE: Considerar múltiplos DECIDE IF aninhados com early exit, em vez de DECIDE FOR EVERY

    Escalabilidade

    • Modo batch: Processamento sequencial de registros; sem paralelismo
    • Transações: Cada registro constitui uma transação; sem batching de transações
    • Memória: Consumo mínimo; apenas 7 variáveis locais + estruturas Adabas

    Riscos Operacionais

    • RO-001 (Indisponibilidade de N9013Q06): Campo L001-INDC-SITC-SIMU não pode ser validado; impede execução quando este campo é fornecido. Risco: Batch interrompido.
    • RO-002 (Indisponibilidade de R9012001): Impressão ANTES/DEPOIS falha; perda de auditoria. Risco: Compliance.
    • RO-003 (Corrupção de dados por validação fraca): Datas ou números inválidos podem ser aceitos e persistidos. Risco: Integridade de dados.
    • RO-004 (Exceção não capturada em CALLNAT): Se N9013Q06 lança exceção, programa termina abruptamente. Risco: Indisponibilidade de serviço.
    • RO-005 (Modo simulação vs produção): Se EFETIVA é passado incorretamente, simulação real é executada (DELETE/UPDATE real). Risco: Perda de dados.

    Riscos de Segurança

    • RS-001 (Sem validação de autorização): Programa não valida se usuário tem permissão de alterar/excluir. Risco: Alterações não autorizadas.
    • RS-002 (Sem auditoria de mudanças): Apenas impressão ANTES/DEPOIS; sem log persistente de quem alterou/deletou. Risco: Rastreabilidade limitada.
    • RS-003 (ISN como único identificador): Se ISN for previsível ou obtido externamente, risco de alteração/deleção de registros errados. Risco: Integridade de dados.

    Riscos de Manutenção

    • RM-001 (Dependências oscuras): Lógica de validação acoplada a N9013Q06; sem documentação clara. Risco: Dificuldade de manutenção.
    • RM-002 (Subroutine única grande): MOVE-CAMPOS-NAO-NULL é 310 linhas de DECIDE para cada campo; frágil a mudanças de campo. Risco: Propensão a bugs.
    • RM-003 (Estrutura de dados inferida): L9012001 não disponível; comentários do código são únicas fontes de verdade. Risco: Dessincronização se campos mudarem.

    12. Refatoração e Oportunidades de Melhoria

    Oportunidades de Refatoração em Natural

    • Separar Validação em Subroutines: Criar subroutines para cada grupo de validação (obrigatórios, opcionais, externos) em vez de DECIDE FOR EVERY monolítico
    • Encapsular Lógica de Edição Numérica: Extrair validação de números com decimais em função reutilizável
    • Usar REDEFINE ou ARRAY para MOVE-CAMPOS: Em vez de 10 WHENs idênticos, usar loop sobre array de campos
    • Adicionar Error Handling: Envolver CALLNAT em ON ERROR para capturar exceções
    • Tornar Impressão Opcional: Adicionar parâmetro PRINT-REPORT para permitir skip de WRITE(1)

    Simplificações Possíveis

    • Validação de data com 4 passos (check empty, check format, check range) pode ser feita em 1 com função de data do Natural
    • Múltiplas operações Adabas (GET → UPDATE/DELETE → TRANSACTION) podem ser combinadas em única operação MODIFY se Natural suportar
    • Impressão dupla (ANTES/DEPOIS) pode ser substituída por diferença (delta) em modo simulação

    Melhorias de Manutenibilidade

    • Adicionar comentários claros explicando padrão NULL, modo simulação, e convenção de retorno de N9013Q06
    • Criar mapa de versões de campos (N8→N9 para NUMR-DOCM-COBR em SMP-0405/2012)
    • Documentar estrutura de L9012001, A9013Q06, L9013Q13 como comentários (ou idealmenteem arquivo externo)
